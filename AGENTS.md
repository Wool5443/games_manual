# Инструкции для работы с проектом

## Проект

«Простофиля» — каталог игр и упражнений на Flask, Jinja и SQLite.
Интерфейс и сообщения приложения — на русском языке.
Страницы рендерятся на сервере; формы используют обычные GET/POST-запросы.
Не добавляйте SPA, frontend-фреймворк или сборку JavaScript без необходимости задачи.

## Карта кода

- `app.py` — запуск сервера и инициализация базы.
- `games_manual_app/__init__.py` — `create_app()` и регистрация компонентов.
- `games_manual_app/config.py` — настройки, схема SQLite, справочники и допустимые значения.
- `games_manual_app/db.py` — соединение через Flask `g`, создание таблиц и начальных справочников.
- `games_manual_app/routes/public.py` — каталог, карточка, личные игры, создание и вложения.
- `games_manual_app/routes/auth.py` — Google OAuth, приглашения и выход.
- `games_manual_app/routes/admin.py` — администрирование, импорт и экспорт.
- `games_manual_app/access.py` — роли, проверка владельца и декораторы доступа.
- `games_manual_app/games.py` — фильтры, сортировка, валидация, редактирование и удаление игр.
- `games_manual_app/admin_services.py` — пакетное изменение справочников и доступа.
- `games_manual_app/files.py`, `import_export.py` — вложения и обмен данными.
- `templates/base.html` — общий каркас; `templates/partials/game_body.html` — общее содержимое игры.
- `static/` — CSS и небольшие скрипты отдельных страниц.
- `tests/test_views.py` — регрессионные тесты через `unittest` и Flask test client.
- `TODO.md` — запланированные задачи; выполняйте только запрошенную работу.

## Правила изменений

- Меняйте минимальный необходимый участок, переиспользуйте существующие функции и шаблоны.
- Сохраняйте параметры поиска, фильтрации, сортировки и адрес возврата при изменении навигации.
- Проверяйте права на сервере: скрытая кнопка не заменяет проверку доступа.
- Посетитель читает каталог и вложения; редактор добавляет игры и меняет только свои; администратор меняет любые игры и управляет доступом.
- Владельца определяет нормализованный `created_by_email`; `ADMIN_EMAILS` имеет приоритет над ролью из базы.
- SQL-значения передавайте параметрами. Имена сортируемых полей и направление сортировки проверяйте по допустимому списку.
- Сохраняйте автоматическое экранирование Jinja для пользовательского текста.
- Типы игры хранятся строкой с разделителем-запятой: используйте `parse_multi_categories` и `join_multi_categories`.
- Имена вложений хранятся JSON-массивом в `files_json`, сами файлы — в `uploads/`.
- При изменении схемы обеспечьте совместимость с существующей базой; не ограничивайтесь правкой `CREATE TABLE`.
- Не изменяйте реальные данные в `instance/`, `uploads/` и `docker_data/` для проверок. Используйте временные каталоги и базу.
- Не включайте секреты, OAuth-токены, `.env`, базы и загруженные файлы в коммиты.

## Интерфейс

- Сохраняйте однотонные тёмные поверхности, красный акцент, простые границы и общий радиус скругления.
- Используйте нативные `select`, чекбоксы и `<dialog>`; сохраняйте подписи, клавиатурную навигацию и видимый фокус.
- Не возвращайте градиенты, тени, размытие и анимацию раскрытия карточек без явного запроса.
- CSS разделён по назначению: `palette.css` — переменные, `styles.css` — каркас и администрирование, `forms.css` — формы, `cards.css` — карточки и диалог.
- Сохраняйте адаптивность и перенос длинных названий и категорий.

## Запуск и проверка

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

Настройки берутся из окружения; обычный запуск Python сам не загружает `.env`.
Docker Compose подключает `.env` через `env_file`.

```bash
.venv/bin/python -m unittest discover -s tests -v
git diff --check
```

Если окружение уже существует, используйте его вместо создания нового.
Тесты создают временную SQLite-базу и подставляют пользователей через сессию.
Они проверяют HTML, формы, поиск, сортировку, доступ и сохранение данных, но не настоящий Google OAuth, JavaScript или визуальный вид.
Для изменения поведения добавляйте целевой регрессионный тест; для изменений CSS и JavaScript проверяйте соответствующие страницы в браузере, включая узкий экран и клавиатуру.
Для правок только документации достаточно проверки diff; не заявляйте о проверках, которые не выполнялись.

## Особенности обмена данными

- Импорт SQLite заменяет файл базы целиком и может заменить пользователей доступа и приглашения.
- CSV обновляет игры с совпадающими ID и добавляет остальные; вложения должны уже существовать в `uploads/`.
- Экспорт базы и CSV не включает содержимое вложений: полная резервная копия требует базы и каталога `uploads/`.
- `scripts/import_game_manual.py` — отдельный устаревший Excel-импортёр. Он требует `openpyxl` и содержит несовместимый импорт констант из `app.py`; не используйте его как штатный способ импорта без исправления.
